# 22세기 브르마블 · 사람 4명 함께 플레이 설계서

작성 2026-11-15 · 적용 대상 Level 1~4 (`level1.html` ~ `level4.html`)

## 1. 목표

사람끼리 최대 4명이 같은 판을 한다. 빈 자리는 AI가 채운다. 방식은 두 가지다.

| 방식 | 언제 쓰나 | 필요한 것 |
|---|---|---|
| 📱 **한 기기에서** (돌려하기) | 교실·가족이 폰/패드 하나로 | 없음 (지금 바로 됨) |
| 🌐 **온라인 방** | 각자 자기 폰·패드로 | Cloudflare 서버 1개 (무료 플랜) |

모든 레벨이 **같은 공통 모듈 `mp-core.js` 하나**로 움직이므로, 레벨마다 다르게 동작하지 않는다.

## 2. 고친 문제 (전에는 어땠나)

| 레벨 | 전 | 후 |
|---|---|---|
| Level 1 | 사람 1명만 가능 | 사람 1~4명 + AI 0~3명 (합계 2~4명) |
| Level 2 | 자리별 사람/AI 토글은 있었지만 넘김 화면 없음 | 공통 넘김 화면 추가 |
| Level 3·4 | 사람 수는 고를 수 있었지만, ‘내 국가’·세금·대출 버튼이 **항상 1번 플레이어**에게 적용되는 버그 | 화면의 ‘나’ = 지금 차례인 사람 (`ME()`) |
| 공통 | 넘김 카드가 레벨마다 달랐음(Level 3·4만 1.2초 자동) | 4개 레벨 같은 넘김 화면 · 눌러야 시작 |
| 공통 | 온라인 없음 | 방 코드 4자리로 최대 4명 접속 |

## 3. 구조

```
 [호스트 기기]  게임을 실제로 돌림 (주사위·판정·AI 전부)
      │  ① 상태가 바뀔 때마다 게임 상태(JSON) 전송
      ▼
 [Cloudflare Worker + Durable Object]  방 1개 = 객체 1개, 자리 배정·전달만 함
      │  ② 참가자 모두에게 그대로 전달 (마지막 상태는 보관 → 늦게/다시 들어와도 바로 보임)
      ▼
 [참가자 기기 ×3]  받은 상태로 같은 화면을 그림 (화면의 ‘나’ = 내 자리)
      │  ③ 내 차례에 누른 버튼을 "어떤 버튼인지"로 보냄  {data-ask:"buy"}
      ▼
 [호스트]  같은 버튼을 찾아 대신 눌러 줌 → 결과가 다시 ①로 퍼짐
```

**왜 이렇게 했나 (초보자용 설명)**
- 게임 규칙 코드가 레벨마다 수천 줄이다. 서버로 옮기면 전부 다시 짜야 한다.
- 대신 호스트 브라우저가 지금처럼 게임을 돌리고, 서버는 ‘우체부’ 역할만 한다.
- 모든 레벨이 이미 게임 상태를 JSON으로 저장·이어하기 하고 있어서, 그 JSON을 그대로 보내면 다른 기기에서도 같은 화면이 그려진다.
- 그래서 게임 규칙은 한 줄도 바꾸지 않고 온라인이 된다.

## 4. 화면 흐름

**한 기기에서**
1. 설정 화면에서 사람 수(2~4명)와 이름을 고른다 (Level 2는 자리별 ‘사람/AI’ 토글).
2. 사람 차례가 오면 `📱 PASS THE DEVICE · ○○님 차례` 화면 → **내 차례 시작**을 누른다.
3. 화면의 현금·순위·내 회사/내 국가가 그 사람 것으로 바뀐다.
4. 같은 사람이 이어서 하면(나머지가 AI) 넘김 화면은 생략한다.
5. 👥 함께 플레이 → ‘한 기기에서’에서 넘김 화면을 끌 수 있다.

**온라인 방**
1. 호스트: 설정 화면 오른쪽 위 **👥 함께 플레이 → 🌐 온라인 방 → 이름 → 🏠 방 만들기** → 방 코드(예: `K7QM`)와 초대 링크.
2. 참가자: 같은 레벨 화면에서 **🚪 참여**에 코드 입력, 또는 초대 링크(`level3.html?room=K7QM`)를 열기.
3. 호스트: 다 모이면 **✅ 이 인원으로 설정 채우기** → 평소처럼 **게임 시작**.
4. 진행 중 화면 아래 알약에 `🌐 K7QM · 4명 접속 · 민수님 차례` 표시. 내 차례면 초록으로 깜빡이고 진동.
5. 남의 차례에 버튼을 누르면 `⏳ ○○님 차례입니다` 안내만 뜨고 아무 일도 없다.

## 5. 규칙 (예외 상황)

| 상황 | 처리 |
|---|---|
| 참가자가 새로고침·잠깐 끊김 | 같은 기기로 다시 열면 자동으로 **같은 자리**로 복귀, 마지막 화면 바로 표시 |
| 참가자가 끊긴 채 차례가 옴 | 알약에 `연결 끊김 → 대신 선택 가능` · 호스트가 대신 누를 수 있음 |
| 호스트 새로고침 | 방은 유지. 호스트가 **이어하기**를 누르면 저장된 판으로 계속 |
| 게임 시작 후 새 사람 | 들어올 수 없음 (자리 잠금) |
| 다른 레벨 화면에서 참여 | 거절: “다른 레벨의 방입니다” |
| 5번째 사람 | 거절: “방이 가득 찼습니다 (최대 4명)” |
| 경매처럼 차례가 아닌 사람이 고를 때 | 그 사람 기기로 선택이 감 (`MP.who(q)`) |
| Level 3·4 세금·대출·관세·크립토 버튼 | 자기 차례에만 · 자기 국가에 적용. 비밀투표(bid)는 언제든 |

## 6. 파일

| 파일 | 역할 |
|---|---|
| `mp-core.js` | 공통 모듈: 넘김 화면, `ME()`, 로비 UI, 온라인 연결, 클릭 전달·재생 |
| `mp-config.js` | 온라인 서버 주소 (`window.MP_SERVER`) — 배포 후 1줄 입력 |
| `level1~4.html` | 끝에 어댑터 1개씩 (`MP.bind({...})`) + `S.players[0]` → `ME()` |
| `server/src/room-core.js` | 방 규칙 (자리 배정·잠금·재접속·전달) — 서버·시험 서버 공용 |
| `server/src/worker.js` | Cloudflare Worker + Durable Object `Room` |
| `server/wrangler.toml` | Cloudflare 설정 (무료 플랜용 SQLite DO) |
| `server/dev-relay.mjs` | 내 PC 시험용 방 서버 (같은 room-core 사용) |
| `tests/mp-room.cjs` | 방 규칙 자동 시험 |

### 레벨 어댑터가 알려 주는 것

| 항목 | 뜻 |
|---|---|
| `players / turn / state / setState / render` | 레벨마다 다른 변수 이름(S, G)을 공통 이름으로 |
| `actionEl` | ‘게임을 바꾸는 버튼’이 무엇인지 (Level 1·3·4 `[data-ask]` 등, Level 2 `#roll`·선택 버튼·고속철 칸) |
| `prepareForm / applySeats` | 방 인원을 설정 화면·플레이어 자리에 채우기 |
| `clientMode` | 참가자 기기에서는 게임 진행·저장을 끔(호스트만 진행) |

### 메시지 규약 (JSON)

| 방향 | 메시지 |
|---|---|
| 서버→본인 | `{t:'welcome', seat, host, code}` |
| 서버→모두 | `{t:'roster', members:[{seat,name,online,host}], started}` |
| 호스트→참가자 | `{t:'state', d:'{"s":게임상태,"a":결정할사람,"t":차례,"open":선택중}'}` |
| 참가자→호스트 | `{t:'act', d:{id,data,cls}}` → 호스트는 `{t:'act', seat, d}` 로 받음 |
| 호스트→서버 | `{t:'start'}` 자리 잠금 |

상태 크기 실측: Level 1 약 4KB · Level 2 약 4KB · Level 3·4 약 14KB (서버 한도 900KB).

## 7. Cloudflare 배포 (본인 PC에서 1회)

```bash
cd mable22-play/server
npm install
npx wrangler login          # 브라우저로 Cloudflare 로그인
npx wrangler deploy         # → https://mable22-mp.<계정>.workers.dev 주소가 나옴
```

그다음 `mp-config.js` 한 줄을 고치고 푸시한다.

```js
window.MP_SERVER = 'wss://mable22-mp.<계정>.workers.dev';
```

- 게임 화면을 Cloudflare Pages로 옮기면 `wrangler.toml`의 `ALLOWED_ORIGINS`에 그 주소를 쉼표로 추가한다.
- 무료 플랜(2025-04부터 SQLite 기반 Durable Object 사용 가능): 하루 요청 10만 건, 실행 시간 13,000 GB-초.
  - 받는 웹소켓 메시지는 20개가 요청 1건으로 계산되고 보내는 메시지는 무료 → 4인 1판(1시간)에 요청 수백 건 수준.
  - 실행 시간은 열린 방 1개가 약 0.125GB로 계산되어 **하루 합계 약 28시간 분량의 방**까지 무료. 수업용 규모는 충분하고, 넘으면 그날은 새 연결이 실패한다(요금이 자동 청구되지는 않음).
  - 더 늘어나면 ‘웹소켓 Hibernation API’로 바꿔 대기 시간 비용을 없앤다(9장).

**내 PC에서 먼저 시험**: `npm run relay` 후 게임 주소 뒤에 `?mp=ws://localhost:8787` 을 붙여 창 2~4개로 연다.

## 8. 검증 결과 (2026-11-15)

- 한 기기: Level 1~4 사람 2~3명 판에서 넘김 화면·‘나’ 전환 확인, 오류 0.
- 온라인 4명(호스트+3): Level 1~4 모두 한 라운드 이상 진행, 4개 기기의 라운드·차례·현금이 모두 일치, 오류 0.
- Cloudflare 실제 런타임(`wrangler dev`)으로 Level 4 4인 진행 확인.
- 남의 차례 클릭 차단, 호스트 대리 클릭 차단, 참가자 세금 변경이 자기 국가에만 적용, 새로고침 후 같은 자리 복귀 확인.
- 기존 시험(`tests/*.cjs`) 모두 통과.

## 9. 한계와 다음 단계

1. **연출**: 참가자 화면은 결과 상태를 받아 그리므로 주사위 굴림·화살표 연출 일부가 호스트보다 단순하게 보인다. → 다음 단계에서 연출 이벤트만 따로 보내기.
2. **호스트 의존**: 호스트 화면이 꺼지거나 앱을 닫으면 게임이 멈춘다. → 호스트는 충전기 연결·화면 켜 두기 안내. 장기적으로는 호스트 넘기기.
3. **Beginning·Crazy World**: 이번 범위 밖. 같은 어댑터 방식으로 붙일 수 있다.
4. **결제 라인**: 이 서버(Cloudflare Worker)에 결제 확인 경로를 추가하는 순서로 진행 (할 일 목록 3번).
5. **서버 비용 최적화**: 동시 방이 많아지면 Durable Object를 웹소켓 Hibernation API로 전환(방 상태를 저장소에 보관).
