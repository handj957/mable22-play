# 22세기 브르마블 · 사람 4명 함께 플레이 설계서

작성 2026-11-15 · 개정 2026-11-18 (빠른 매칭 추가: 랜덤 자동 매칭 + 친구 방)

적용 대상 8개: Level 1~4 (`level1~4.html`) + Beginning 1~4 (`beginning-level1~4.html`)

## 1. 목표

사람끼리 최대 4명이 **각자 자기 폰·패드로** 같은 판을 한다. 빈 자리는 AI가 채운다.
다른 온라인 게임(브롤스타즈·클래시 로얄·어몽어스·카트라이더 등)의 방식처럼 **기본은 빠른 매칭, 아는 사람과는 방**이다.

게임에 접속하면 먼저 고른다.

| 버튼 | 하는 일 | 참고한 방식 |
|---|---|---|
| 🎮 **1인 플레이** | 나 + AI로 바로 시작 | 연습/싱글 모드 |
| ⚡ **빠른 매칭** | 같은 게임에 접속한 사람과 **자동으로 묶여** 바로 시작. 이름 입력도 없음 | 브롤스타즈·카트라이더 ‘빠른 시작’, 대기 인원·카운트다운 표시 |
| 👥 **친구와 하기** | 방을 만들어 4자리 코드/링크로 친구 초대, 호스트가 시작 | 어몽어스·클래시 로얄 ‘친구 방’ |

- 한 기기를 돌려 가며 하는 방식은 없앴다(2026-11-15 결정).
- 나중에 바꾸려면 설정 화면 오른쪽 위 **👥 멀티플레이** 버튼.
- 8개 게임(Level 1~4, Beginning 1~4)이 **같은 공통 모듈 `mp-core.js` 하나**로 움직인다.
- 필요한 것: Cloudflare 서버 1개 (무료 플랜) — 7장.

### 빠른 매칭 규칙 (쉽고 빠르게)

| 상황 | 시작 |
|---|---|
| 4명이 모임 | **3초 뒤** 자동 시작 |
| 2~3명이 모임 | 둘째가 들어온 뒤 **15초 뒤** 자동 시작, 빈 자리 AI |
| 누구든 ‘▶ 지금 시작’ | 2명 이상이면 바로 시작 |
| 혼자 기다리는 중 | ‘🎮 AI와 혼자 하기’로 바로 1인 플레이 / ‘취소’ |

- 매칭은 **같은 게임끼리만** (Beginning 3 대기열과 Level 3 대기열은 따로).
- 한 방에 사람을 넣어 주는 시간은 30초. 그 사이 4명이 안 차도 15초 규칙으로 시작된다.
- 시작하는 순간 **접속 중인 사람만** 남기고 자리를 1·2·3·4번으로 정리, 1번 기기가 게임을 돌린다(호스트). 사람이 직접 호스트를 정할 필요 없음.
- 이름은 처음 한 번 자동(`플레이어1234`), ‘친구와 하기’ 창에서 바꾸면 다음 매칭부터 그 이름.

## 2. 바뀐 점

| 레벨 | 전 | 후 |
|---|---|---|
| Level 1 | 사람 1명 | 설정은 내 이름 + AI 1~3명. 온라인 방이면 방 인원(최대 4명)이 자동으로 자리에 앉음 |
| Level 2 | 자리별 사람/AI 토글(한 기기 돌려하기) | 토글 삭제. 1번 = 나, 나머지 = AI, 온라인 방이면 ‘온라인’ 표시 |
| Level 3·4 | 사람 수 1~4명 선택(한 기기 돌려하기) + 넘김 카드 | 사람 수 줄·넘김 카드 삭제. 온라인 방 인원으로만 사람 자리가 늘어남 |
| Level 3·4 | ‘내 국가’·세금·대출 버튼이 항상 1번 플레이어에게 적용되던 버그 | 화면의 ‘나’ = 내 자리 (`ME()`) |
| Beginning 1~4 | 혼자 또는 한 기기 돌려하기 | Level 1~4와 똑같이 온라인 방 + 1인/멀티 선택 (Beginning 3·4의 넘김 카드·사람 수 줄 삭제) |
| 공통 | 온라인 없음 | 방 코드 4자리로 최대 4명 접속 · 접속 시 1인/멀티 선택 |

## 3. 구조

```
 [호스트 기기]  게임을 실제로 돌림 (주사위·판정·AI 전부)
      │  ① 상태가 바뀔 때마다 게임 상태(JSON) 전송
      ▼
 [Cloudflare Worker + Durable Object]  방 1개 = 객체 1개, 자리 배정·전달만 함
      │  ② 참가자 모두에게 그대로 전달 (마지막 상태는 보관 → 늦게/다시 들어와도 바로 보임)
      ▼
 [참가자 기기 ×3]  받은 상태로 같은 화면을 그림 (화면의 ‘나’ = 내 자리)
      │  ③ 내 차례에 누른 버튼을 "어떤 버튼인지"로 보냄  {data-ask:"buy"}
      ▼
 [호스트]  같은 버튼을 찾아 대신 눌러 줌 → 결과가 다시 ①로 퍼짐
```

**왜 이렇게 했나 (초보자용 설명)**
- 게임 규칙 코드가 레벨마다 수천 줄이다. 서버로 옮기면 전부 다시 짜야 한다.
- 대신 호스트 브라우저가 지금처럼 게임을 돌리고, 서버는 ‘우체부’ 역할만 한다.
- 모든 레벨이 이미 게임 상태를 JSON으로 저장·이어하기 하고 있어서, 그 JSON을 그대로 보내면 다른 기기에서도 같은 화면이 그려진다.
- 그래서 게임 규칙은 한 줄도 바꾸지 않고 온라인이 된다.

## 4. 화면 흐름

**⚡ 빠른 매칭**
1. 접속 → **빠른 매칭** 한 번 누름.
2. 대기 화면: `🔎 상대를 찾는 중…` → `👀 3명 모였습니다 · 12초 뒤 시작` → `🎉 4명 모두 모였습니다! · 3초 뒤 시작`. 사람이 들어오면 짧게 진동.
3. 시간이 되면 모두의 화면이 자동으로 게임으로 넘어간다(누구도 설정을 누를 필요 없음).

**👥 친구와 하기**
1. 호스트: **친구와 하기 → 이름 → 🏠 방 만들기** → 방 코드(예: `K7QM`)와 초대 링크 복사.
2. 친구: 같은 게임 화면에서 **친구와 하기 → 코드 → 🚪 참여**, 또는 초대 링크(`level3.html?room=K7QM`) 열기.
3. 호스트: 다 모이면 **✅ 이 인원으로 설정 채우기** → **게임 시작**. (방을 나가면 설정은 다시 ‘나 + AI’)

**공통(게임 중)**
- 화면 아래 알약에 `🌐 K7QM · 4명 접속 · 민수님 차례`. 내 차례면 초록으로 깜빡이고 진동.
- 남의 차례에 버튼을 누르면 `⏳ ○○님 차례입니다` 안내만.
- 각자 화면의 현금·순위·내 회사/내 국가는 항상 **자기 것**.

## 5. 규칙 (예외 상황)

| 상황 | 처리 |
|---|---|
| 참가자가 새로고침·잠깐 끊김 | 같은 기기로 다시 열면 자동으로 **같은 자리**로 복귀, 마지막 화면 바로 표시 |
| 참가자가 끊긴 채 차례가 옴 | 알약에 `연결 끊김 → 대신 선택 가능` · 호스트가 대신 누를 수 있음 |
| 호스트 새로고침 | 방은 유지. 호스트가 **이어하기**를 누르면 저장된 판으로 계속 |
| 게임 시작 후 새 사람 | 들어올 수 없음 (자리 잠금) |
| 다른 게임 화면에서 참여 | 거절: “다른 게임의 방입니다” |
| 빠른 매칭 중 들어가려던 방이 그새 시작/가득 | 자동으로 다른 매칭 방을 다시 받음(최대 3번) |
| 빠른 매칭 대기 중 나감 | 자리 바로 반납, 남은 사람이 1명이면 카운트다운 취소 |
| 5번째 사람 | 거절: “방이 가득 찼습니다 (최대 4명)” |
| 경매처럼 차례가 아닌 사람이 고를 때 | 그 사람 기기로 선택이 감 (`MP.who(q)`) |
| Level 3·4 세금·대출·관세·크립토 버튼 | 자기 차례에만 · 자기 국가에 적용. 비밀투표(bid)는 언제든 |

## 6. 파일

| 파일 | 역할 |
|---|---|
| `mp-core.js` | 공통 모듈: `ME()`, 온라인 방 로비 UI, 연결, 클릭 전달·재생 |
| `mp-config.js` | 온라인 서버 주소 (`window.MP_SERVER`) — 배포 후 1줄 입력 |
| `level1~4.html`, `beginning-level1~4.html` | 끝에 어댑터 1개씩 (`MP.bind({...})`) + `S.players[0]` → `ME()` |
| `server/src/room-core.js` | 방 규칙 (자리 배정·잠금·재접속·전달) + 빠른 매칭(대기열·카운트다운·자리 정리) — 서버·시험 서버 공용 |
| `server/src/worker.js` | Cloudflare Worker + Durable Object `Room`(방) · `Matchmaker`(게임별 대기열), `GET /match?lv=` |
| `server/wrangler.toml` | Cloudflare 설정 (무료 플랜용 SQLite DO) |
| `server/dev-relay.mjs` | 내 PC 시험용 방 서버 (같은 room-core 사용) |
| `tests/mp-room.cjs` | 방 규칙 자동 시험 |

### 레벨 어댑터가 알려 주는 것

| 항목 | 뜻 |
|---|---|
| `players / turn / state / setState / render` | 레벨마다 다른 변수 이름(S, G)을 공통 이름으로 |
| `actionEl` | ‘게임을 바꾸는 버튼’이 무엇인지 (Level 1·3·4 `[data-ask]` 등, Level 2 `#roll`·선택 버튼·고속철 칸) |
| `prepareForm / applySeats` | 방 인원을 설정 화면·플레이어 자리에 채우기 |
| `autoStart` | 빠른 매칭이 시작되면 호스트 기기에서 게임 시작 버튼을 대신 누름 |
| `clientMode` | 참가자 기기에서는 게임 진행·저장을 끔(호스트만 진행) |

### 메시지 규약 (JSON)

| 방향 | 메시지 |
|---|---|
| 누구나→서버(HTTP) | `GET /match?lv=level3[&skip=코드]` → `{code}` 빠른 매칭 방 코드 |
| 서버→본인 | `{t:'welcome', seat, host, code, pub, go}` — `pub`=매칭 방, `go`=시작됨 |
| 서버→모두 | `{t:'roster', members:[{seat,name,online,host}], started, pub, startIn}` — `startIn`=시작까지 남은 ms |
| 호스트→참가자 | `{t:'state', d:'{"s":게임상태,"a":결정할사람,"t":차례,"open":선택중}'}` |
| 참가자→호스트 | `{t:'act', d:{id,data,cls}}` → 호스트는 `{t:'act', seat, d}` 로 받음 |
| 호스트→서버 | `{t:'start'}` 친구 방 자리 잠금 |
| 매칭 방 누구나→서버 | `{t:'go'}` 2명 이상이면 지금 시작 |

상태 크기 실측: Level·Beginning 1·2 약 4KB · 3·4 약 13~14KB (서버 한도 900KB).

같은 방은 같은 게임 화면끼리만 들어올 수 있다 (예: `beginning-level3` 방에 `level3` 화면으로는 참여 불가).

## 7. Cloudflare 배포

### 방법 A (사용 중) — Cloudflare가 GitHub 저장소에서 직접 배포 (2026-11-18 배포 완료)

- 서버 주소: **`https://mable22-mp.handj957.workers.dev`** (게임은 `wss://`로 접속, `mp-config.js`에 기록됨)
- Cloudflare 대시보드 → Workers & Pages → Create application → Import a repository → `handj957/mable22-play`
- 설정값

| 칸 | 값 |
|---|---|
| Project name | `mable22-mp` (`server/wrangler.toml`의 name과 같아야 함) |
| Build command | (비움) |
| Deploy command | `cd server && npx wrangler deploy` |
| Enable Preview builds | 끔 |

- 이후 `main`에 푸시하면 Cloudflare가 자동으로 다시 배포한다. 토큰·GitHub 비밀값은 필요 없다.
- 실제 서버 점검: GitHub **Actions → Check multiplayer server** (`tests/mp-live.mjs`: 서버 응답 → 빠른 매칭 표 → 2명 접속·지금 시작·호스트 지정 → 상태 전달). `server/`·`mp-config.js`를 푸시하면 자동 실행.
- 저장소 이름(`mable22-play`, 게임 파일 전체)과 서버 이름(`mable22-mp`, `server` 폴더만)은 다르다.

### 방법 B — 본인 PC에서 직접



```bash
cd mable22-play/server
npm install
npx wrangler login          # 브라우저로 Cloudflare 로그인
npx wrangler deploy         # → https://mable22-mp.<계정>.workers.dev 주소가 나옴
```

그다음 `mp-config.js` 한 줄을 고치고 푸시한다.

```js
window.MP_SERVER = 'wss://mable22-mp.<계정>.workers.dev';
```

- 게임 화면을 Cloudflare Pages로 옮기면 `wrangler.toml`의 `ALLOWED_ORIGINS`에 그 주소를 쉼표로 추가한다.
- 무료 플랜(2025-04부터 SQLite 기반 Durable Object 사용 가능): 하루 요청 10만 건, 실행 시간 13,000 GB-초.
  - 받는 웹소켓 메시지는 20개가 요청 1건으로 계산되고 보내는 메시지는 무료 → 4인 1판(1시간)에 요청 수백 건 수준.
  - 실행 시간은 열린 방 1개가 약 0.125GB로 계산되어 **하루 합계 약 28시간 분량의 방**까지 무료. 수업용 규모는 충분하고, 넘으면 그날은 새 연결이 실패한다(요금이 자동 청구되지는 않음).
  - 더 늘어나면 ‘웹소켓 Hibernation API’로 바꿔 대기 시간 비용을 없앤다(9장).

**내 PC에서 먼저 시험**: `npm run relay` 후 게임 주소 뒤에 `?mp=ws://localhost:8787` 을 붙여 창 2~4개로 연다.

## 8. 검증 결과 (2026-11-15 · 2026-11-18)

- 온라인 4명(호스트+3): Level 1~4와 Beginning 1~4, 8개 게임 모두 한 라운드 이상 진행, 4개 기기의 라운드·차례·현금이 모두 일치, 오류 0.
- Cloudflare 실제 런타임(`wrangler dev`)으로 Level 4 4인 진행 확인.
- 남의 차례 클릭 차단, 호스트 대리 클릭 차단, 참가자 세금 변경이 자기 국가에만 적용, 새로고침 후 같은 자리 복귀 확인.
- 접속 시 1인/멀티 선택 창: 8개 게임 모두 표시, 1인 플레이 선택 후 나 + AI로 정상 진행
- 혼자 하기(나 + AI): 8개 게임 넘김 화면 없이 정상 진행, 설정 화면에 사람 수·사람/AI 토글이 보이지 않음.
