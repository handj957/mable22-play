# Level 3·4 두 주사위 설계 및 작업 기록

2026-10-31 / 일반·교육용 Level 3·4

## 분석 결과와 구현 난이도

중간. 내부는 이미 7개 논리 주사위(move/pol/eco/mil/dip/res/re)를 갖지만, actionMini·renderAct·renderHStage와 throwDice는 현재 분야 하나만 크게 표시했다. rollA는 여러 번 래핑되어 효과 화살표와 진행 표시를 추가하며, roundEnd·테러·정치·전쟁은 d12를 직접 호출한다. 화면의 한 개를 단순히 복제하면 판정 경로가 빠진다.

## 두 주사위와 역할

| 물리 주사위 | 논리 역할 | 입력 → 결과 | 영향을 받는 기능 |
|---|---|---|---|
| ① 이동 D12 | move | 1~12 → moveSteps → land | 출발 보너스, 도착칸, 이동값 기준 시설 통행료, 12 추가 턴·3연속 억류 |
| ② 분야 판정 D12 | pol/eco/mil/dip/res/re 및 자동 판정 | 1~12 + 기존 보정 → 기존 임계값 | 선거·혁명, 금리·경기, 전투·탈출, 외교·첩보, 자원가격, 건설 반값·부동산 |

두 값은 합산하지 않는다. 2D6로 바꾸지 않는다. 기존 1D12 균등분포·난수 호출 횟수·임계값을 유지한다. ②를 추가로 굴려 이동하지 않으며, ①을 전투 보정에 재사용하지 않는다.

## 배선

- 플레이어 행동/AI → 기존 takeTurn·명령 함수 → rollA(domain) → 기존 연출/화살표 래퍼 → d12(domain) → DualDice.roll → 단일 난수 → 기존 S.dv[domain]·보정·효과.
- 자동 결산/테러/정치 등 → d12(domain) 또는 d12() → ② 판정 기록 → 기존 계산.
- 이름 없는 기존 d12()는 자동 판정으로 분류한다. AI 점수의 난수 보정 등도 기존 호출을 그대로 유지하며, 개별 세계 판정의 의미와 보정은 기존 코드가 담당한다.
- DualDice.state는 게임 상태 S.dicePair에 마지막 값/분야/활성 채널을 저장한다. 기존 S.dv는 그대로 두어 기존 계산과 호환한다.
- 저장: 기존 save의 S 전체 직렬화에 포함. 구버전 저장은 처음 표시/굴림 때 S.dv로부터 지연 초기화.
- UI: 중앙 행동창·행동 탭·상단 진행 표시에서 두 개를 상시 구분. 이동/판정의 이름·색·숫자로 구별한다. 숫자는 마지막 결과이고 선택 버튼이 아니다. 던지기 연출은 실제 사용 중인 주사위 하나만 재생한다.

## 향후 플레이어 선택 기능의 경계

현재는 기존 행동이 주사위를 자동 결정한다. 선택 기능은 아직 활성화하지 않는다. 추후 행동별 허용 채널 검증 → 선택 → 한 번의 굴림 → 결과 소비 → 턴 완료 상태 전이를 추가해야 한다. 두 값 중 유리한 결과 선택, 무제한 재굴림, 판정 선택으로 이동 누락을 허용하면 안 된다. 플레이어/턴/요청 ID와 중복 실행 방지도 그 단계에서 도입한다. 이동을 포기하고 판정을 하는 자유 선택은 별도 규칙과 AI 밸런스가 필요하다.

## 실행 순서와 검증

1. 기존 호출 경로·재정의·저장·표시 조사.
2. 공통 채널 분배기와 구버전 상태 초기화 구현.
3. 이동과 분야별 호출 연결, 네 페이지의 세 표시 영역에 두 주사위 배치.
4. 난수 경계·분포·채널 독립·저장 복원·기존 이동/판정 연결 검사.
5. 브라우저 사용 가능 시 실제 시작·이동·분야 판정·모바일 배치 검사.
6. 최신 원격 main을 확인하고 한 커밋으로 반영, Pages 배포 결과 확인.

## 원인과 결과 검토

- 이동 난수의 범위를 유지하므로 출발 보너스 빈도와 12 추가 턴 확률은 동일하다.
- 분야 판정 난수의 범위를 유지하므로 성공확률·건설 할인확률·경제 분포는 동일하다.
- 두 주사위 기록은 서로 덮어쓰지 않으며, 기존 분야별 S.dv 기록도 유지한다.
- 새 필드는 UI 및 저장 기록용이다. 기존 통행료·전투·승리 계산이 이 필드를 입력으로 사용하지 않는다.
- Level 4의 지도자·전쟁·다중 승리와 교육용의 교육 기능은 기존 호출 경로를 따른다.
